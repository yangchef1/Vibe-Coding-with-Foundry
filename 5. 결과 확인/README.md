# 5. 결과 확인

이 단계에서는 정책자금 추천부터 영업점 의견서 생성까지 전체 업무 흐름을 실행하고 결과, 오류 처리, 보안 항목을 확인합니다.

## 정책자금 추천 실행

애플리케이션의 `정책자금 추천` 탭에 다음 값을 입력합니다.

| 항목 | 입력값 |
|---|---|
| 업체명 | 한빛정밀 |
| 소재지 | 경기도 화성시 |
| 업종 | 산업용 부품 제조업 |
| 업력 | 2년 4개월 |
| 상시근로자 | 9명 |
| 연매출 | 8억원 |
| 자금 용도 | 전력 사용량을 18퍼센트 줄이는 고효율 생산 설비 교체 |
| 희망 금액 | 1억 5천만원 |
| 특이사항 | 첫 정책자금 신청, 체납과 연체 없음 |

`추천 받기` 버튼을 클릭합니다.

다음 항목을 확인합니다.

- 최대 3개 후보가 서로 다른 근거와 함께 표시됩니다.
- `PF-303`과 같은 문서 고유 코드가 표시됩니다.
- 예상 한도와 필요 서류가 정책자금 가상 데이터와 일치합니다.
- 자료에 없는 승인 여부를 확정하지 않습니다.

## 영업점 의견서로 이어가기

1. 추천 결과에서 `이 추천으로 의견서 작성` 버튼을 클릭합니다.
2. 의견서 탭에 업체 정보, 선택 정책, 추천 근거가 전달되었는지 확인합니다.
3. 아래 내용을 추가로 입력합니다.

    ```text
    영업점 관찰: 주요 거래처 3곳과 2년 이상 거래 중이라고 업체가 설명함
    강점: 설비 견적서와 최근 전력 사용 내역 보유
    위험 요인: 자기자금 10퍼센트 조달 근거 미제출
    추가 확인: 최근 재무제표와 공장등록증
    ```

4. `의견서 초안 만들기` 버튼을 클릭합니다.
5. 사실, 검토 의견, 확인 필요 항목이 구분되는지 확인합니다.

## 최종 결과 확인

- [ ] 추천 결과가 File Search의 가상 정책명과 프로그램 코드를 사용합니다.
- [ ] 추천 결과를 의견서 입력으로 전달할 수 있습니다.
- [ ] 의견서 Agent가 선택 정책을 File Search로 다시 확인합니다.
- [ ] 의견서가 입력하지 않은 사실을 만들어내지 않습니다.
- [ ] 생성 중 상태와 오류 상태가 화면에 표시됩니다.
- [ ] 브라우저 코드와 Git 변경 내용에 API 키나 액세스 토큰이 없습니다.
- [ ] 두 결과에 사람이 확인해야 한다는 안내가 있습니다.

## 문제 해결

### 앱이 실행되지 않을 때

GitHub Copilot app의 현재 세션에 아래 프롬프트를 입력합니다.

```text
앱이 실행되지 않습니다. 현재 터미널 오류를 읽고 원인을 한 가지씩 확인해 주세요. 필요한 수정만 적용한 뒤 npm start로 다시 실행하고 GET /api/health까지 확인해 주세요.
```

### Foundry 연결 오류가 날 때

```text
브라우저에서 Foundry 연결 오류가 납니다. 비밀값은 출력하지 말고 다음 순서로 점검해 주세요: .env 로드 여부, PROJECT_ENDPOINT 형식, 두 Agent 이름, az login 인증, HTTP 상태 코드. 원인을 찾으면 최소 변경으로 수정하고 서버를 다시 시작해 주세요.
```

### 정책 파일과 다른 결과가 나올 때

```text
추천 결과가 업로드한 정책 파일과 맞지 않습니다. 앱이 recommend workflow와 [업무: 정책자금 추천] 표식을 올바른 Agent에 보내는지 확인해 주세요. Foundry Agent나 File Search 설정 문제라면 코드 변경 대신 제가 Foundry에서 확인할 항목을 알려주세요.
```

### 포트 3000을 이미 사용 중일 때

```text
포트 3000을 이미 다른 프로그램이 사용하고 있습니다. 기존 앱 프로세스를 안전하게 종료하고 이 프로젝트를 다시 포트 3000에서 실행해 주세요.
```

### 증상별 확인 항목

| 증상 | 확인할 것 |
|---|---|
| `az`를 찾을 수 없음 | 설치 후 모든 PowerShell 창을 닫고 다시 열었는지 확인 |
| Azure 로그인 계정이 다름 | `az logout` 후 교육용 계정으로 `az login` 재실행 |
| Copilot app에서 세션을 시작할 수 없음 | GitHub 로그인, Copilot 라이선스, 조직의 Copilot CLI 정책 확인 |
| Foundry에서 Agent 생성 불가 | 프로젝트 선택과 Foundry 역할 확인 |
| 파일 업로드가 403 | Foundry 역할과 Storage Blob Data Contributor 역할 확인 |
| 파일 검색 결과가 없음 | 파일 상태가 완료인지, File Search가 현재 Agent 버전에 연결됐는지 확인 |
| 앱 호출이 401 | `az login`을 다시 실행하고 서버 재시작 |
| 앱 호출이 403 | 교육용 계정의 Foundry 프로젝트 권한 확인 |
| 앱 호출이 404 | 프로젝트 엔드포인트와 Agent 이름의 철자 확인 |
| 화면은 열리지만 계속 모의 응답 | Foundry 연결 프롬프트 적용 여부와 서버 재시작 확인 |

## 복구 순서

1. 계정, 프로젝트, Agent 이름, 파일 완료 상태를 다시 확인합니다.
2. Agent 생성이 막히면 미리 준비된 `fund-recommender`와 `branch-opinion-writer`로 애플리케이션 연결부터 계속합니다.
3. 애플리케이션 생성이 막히면 미리 준비된 완성 앱 체크포인트를 새 Copilot 세션에 연결하고 Foundry 연결부터 계속합니다.
4. Azure 전체 장애라면 모의 응답으로 화면 흐름을 완성하고, 준비된 실제 Agent 실행 결과로 연결 구조를 확인합니다.

## 결과물 위치

- 로컬 애플리케이션: 문서 폴더의 `policy-fund-app-<alias>`
- 추천 Agent: Foundry의 `fund-recommender`
- 의견서 Agent: Foundry의 `branch-opinion-writer`
- 지식 저장소: `policy-funds-<alias>`

## 교육용 Azure 계정 로그아웃

PowerShell에서 아래 명령을 실행합니다.

```powershell
az logout
az account clear
```

공용 컴퓨터라면 브라우저의 교육용 Azure 계정에서도 로그아웃합니다. Agent와 업로드 파일 삭제는 전체 결과 확인이 끝난 뒤 영문 alias를 기준으로 수행합니다.

## 같은 Copilot 라이선스로 반복 검증

다른 노트북에 워크숍용 Copilot 라이선스를 연결하지 않아도 됩니다. Copilot 작업은 라이선스가 연결된 노트북에서 매번 새 로컬 폴더와 새 세션으로 반복하고, 다른 노트북은 문서와 발표 화면 확인에 사용합니다.

반복할 때마다 다음 항목을 바꿉니다.

- 새 빈 폴더 사용: `rehearsal-r1`, `rehearsal-r2`
- 새 Agent 이름 접미사 사용: `fund-recommender-r1`, `fund-recommender-r2`
- 새 지식 저장소 이름 사용
- 이전 Copilot 대화가 아닌 새 세션 사용

반복 검증에서는 다음 실패도 의도적으로 확인합니다.

1. 잘못된 Agent 이름을 넣어 404 안내 확인
2. `az logout` 상태에서 401 안내 확인
3. File Search가 없는 Agent에서 근거 부족 확인
4. 포트 3000이 사용 중일 때 복구 프롬프트 확인
5. 다른 실행 위치를 선택했을 때 생성 파일 위치 확인

## 핵심 정리

- Foundry에는 모델뿐 아니라 지침, 도구, 파일 근거를 가진 업무 Agent가 있습니다.
- GitHub Copilot app은 빈 폴더에서 파일 생성, 패키지 설치, 실행, 오류 수정을 수행했습니다.
- 애플리케이션은 복잡한 AI 로직을 다시 만들지 않고 두 Foundry Agent를 업무 순서대로 연결했습니다.
- 추천과 의견서는 최종 판단이 아니라 사람이 검토할 초안입니다.
